4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Boot Records & Session Verification (`last -n 5`)]
* Purpose: Reading the system's `wtmpdb` database to track recent kernel boots, user login events, and session durations.
* Security/System Risk: Unrecognized login sessions or unexpected reboots going unnoticed without log inspection.
* Practical Action: Checking `last` regularly allows defenders to verify legitimate system access and identify unauthorized user logins.

[Audit Target 2: Session Lifecycle Auditing (`systemd-logind` journal)]
* Purpose: Tracking session creation (`c1`, `c2`), user permissions (`hamzaimran`), terminal types (`tty`), and shutdown/cleanup sequences managed by `systemd-logind`.
* Security/System Risk: Stale or lingering user sessions remaining open after a user disconnects, leaving background handles active.
* Practical Action: Monitoring `systemd-logind` provides precise timestamps for when sessions open and close, making it easier to correlate user activity during incident investigation.

[Audit Target 3: Log Priority Filtering (`journalctl -p err..alert`)]
* Purpose: Filtering out standard informational log clutter to highlight priority system errors, kernel messages, and driver warnings.
* Security/System Risk: Critical hardware or service warnings getting buried under thousands of routine system messages.
* Practical Action: Using `-p err..alert` helps administrators immediately spot system instability, hypervisor driver issues, or network initialization failures.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* Ubuntu 24.04 uses `wtmpdb` for boot tracking, recording kernel start times and system uptime history.
* `systemd-logind` assigns unique session IDs (like `c1` for interactive TTY sessions and `c2` for user manager processes) and logs their explicit teardown on shutdown.
* Filtering `journalctl` by log priority (`-p err..alert`) suppresses informational noise, revealing specific WSL2 Hyper-V kernel drivers (`hv_balloon`) and time synchronization (`chronyd`) events.
