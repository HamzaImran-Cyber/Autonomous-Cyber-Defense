4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Interface IP & CIDR Subnet (`172.29.89.97/20` via `ip -4 addr show`)]
* Purpose: Identifies my local IP address (`172.29.89.97`) and CIDR subnet `/20` (Subnet Mask `255.255.240.0`). The output confirms my local network range spans from `172.29.80.1` to broadcast address `172.29.95.255`, giving a total of 4,094 usable host IP slots.
* Security Risk: A large `/20` subnet allows a high volume of local machines to share a single broadcast domain. If an attacker gains access to one compromised host on this subnet, they can perform ARP spoofing, packet sniffing, or local network scanning across all 4,094 IP addresses.
* Defensive Action: Network security teams use micro-segmentation and VLANs to break large subnets down into smaller CIDR blocks (like `/28` or `/29`), isolating critical infrastructure from general host devices.

[Audit Target 2: Kernel Gateway Routing (`172.29.80.1` via `ip route show`)]
* Purpose: Defines how packets leave my operating system. Any traffic destined outside `172.29.80.0/20` is sent directly to default gateway `172.29.80.1` on `eth0`.
* Security Risk: If a malicious actor on the local network performs ARP poisoning, they can trick my system into thinking their MAC address is `172.29.80.1`. This redirects all my internet traffic through the attacker's system before reaching the real router (Man-in-the-Middle attack).
* Defensive Action: Regularly auditing `ip route show` ensures my routing table has not been tampered with. Enterprise networks enforce DHCP Snooping and Dynamic ARP Inspection (DAI) on switches to prevent unauthorized route poisoning.

[Audit Target 3: Network Diagnostics & Latency (`ping` internal vs external)]
* Purpose: Pinging `127.0.0.1` tests internal Linux kernel TCP/IP software health (0.126 ms average latency). Pinging `8.8.8.8` tests physical cabling, local router forwarding, ISP hops, and public ICMP return paths (36.8 ms average latency).
* Security Risk: Leaving ICMP echo responses wide open on public-facing firewalls allows automated reconnaissance tools to discover active live hosts via ping sweeps.
* Defensive Action: Defensive teams configure edge firewalls to block incoming ICMP echo requests from untrusted public IPs while permitting outbound ICMP for internal troubleshooting.
