4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Journald Memory Footprint & Unset Directives (`808.7M` Consumed)]
* Purpose: Evaluate binary log retention limits in system memory/disk.
* Security Risk: Unbounded binary journal growth consumes disk space and can lead to uncoordinated log truncation or system slowdowns.
* Practical Action: Output shows 808.7MB consumed. Grep output confirms `#Storage=persistent` and `#SystemMaxUse=` are commented out with `#`, proving systemd fallback defaults are handling the log size (capping at 10% of filesystem). Production hardening requires explicitly uncommenting and setting `SystemMaxUse=500M`.

[Audit Target 2: Syslog Stream Ingestion (`rsyslog` Active)]
* Purpose: Verify that system events are translated from binary journal streams into standard plaintext `/var/log` paths.
* Security Risk: If `rsyslog` is inactive or misconfigured, security logging falls back strictly to binary journals, preventing standard SIEM or log parsing agents from ingesting `/var/log/auth.log`.
* Practical Action: Confirmed `rsyslog` is active, socket listener `imuxsock` is loaded, and file creation permissions are restricted (`0640` owned by `syslog:adm`).

[Audit Target 3: Logrotate Retention Policy (`rotate 4`, Uncompressed)]
* Purpose: Audit historical log archive lifecycle and disk optimization.
* Security Risk: Uncompressed historical text logs occupy unnecessary storage, while a 4-week retention window (`weekly` + `rotate 4`) may violate longer enterprise compliance requirements (e.g., 90-day retention).
* Practical Action: Identified that compression is currently commented out (`#compress`). Enabling log compression (`compress`) in `/etc/logrotate.conf` reduces historical log storage by up to 90%.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* Lines starting with `#` in `systemd` configuration files reflect compiled-in defaults rather than active user overrides.
* Modern Linux logging uses a two-stage architecture: `journald` captures raw binary events from services/kernel, while `rsyslog` formats and routes them to text files (`/var/log/*`).
* Binary journal limits are managed by `journald.conf` (`SystemMaxUse`), whereas plaintext file limits are managed independently by `logrotate`.
