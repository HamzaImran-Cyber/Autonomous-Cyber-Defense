4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Daemon Startup Sequence (`auditd -f`)]
* Purpose: Debug failure mechanisms during audit framework initialization in user space.
* Security Risk: Unmonitored kernel system calls allow stealthy file modifications and privilege escalation attempts to bypass user-land logging.
* Practical Action: Confirmed that `auditd` parses `/etc/audit/auditd.conf` cleanly, but fails during netlink syscall state initialization (`op=set-enable ... res=failed`).

[Audit Target 2: Kernel Netlink Limitations in Virtualized Container Environments]
* Purpose: Evaluate hypervisor kernel compatibility with native Linux security daemons.
* Security Risk: Assuming kernel-level telemetry is actively auditing system calls without verifying netlink socket response creates critical blind spots.
* Practical Action: Documented that stock Microsoft WSL2 kernels (`6.18.33.2-microsoft-standard-WSL2`) restrict user-space netlink state changes by default. Production deployments on bare-metal or cloud instances (AWS/GCP) execute this natively with active kernel hooks.

[Audit Target 3: Log Storage & Safety Parameters (`auditd.conf`)]
* Purpose: Verify audit log file rotation and disk space safety controls.
* Security Risk: Unbounded log growth can cause disk exhaustion, crashing security services or causing system instability.
* Practical Action: Verified that `/etc/audit/auditd.conf` sets an 8MB log limit with automatic file rotation (`ROTATE`), a 75MB warning threshold (`SYSLOG`), and a 50MB safety suspend (`SUSPEND`).

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* User-space audit tools (`auditd`/`auditctl`) rely on Linux netlink sockets (`NETLINK_AUDIT`) to register syscall watch rules inside Ring 0.
* Differentiating between user-space package installation issues and hypervisor/kernel compilation boundaries is essential for systems auditing.
* Production audit configurations must define strict log rotation (`ROTATE`) and disk space threshold actions (`SYSLOG`/`SUSPEND`) to maintain system stability.
