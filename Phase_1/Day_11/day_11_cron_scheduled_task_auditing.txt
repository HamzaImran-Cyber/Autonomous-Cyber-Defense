4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: User & Root Crontabs (`crontab -l`)]
* Purpose: Checks if any scheduled tasks are currently configured for standard or administrative users.
* Security Risk: Attackers place hidden background scripts in cron so their malware automatically runs every few minutes or at reboot.
* Practical Action: Returning `no crontab` confirms no unauthorized user-level scheduled persistence exists.

[Audit Target 2: System-Wide Cron Folders (`/etc/cron.*`)]
* Purpose: Audits shared directories where the operating system stores global scheduled maintenance scripts.
* Security Risk: If standard users gain write access to `/etc/cron.d` or `/etc/cron.daily`, they can plant scripts that run automatically with full root privileges.
* Practical Action: Verified that all cron configuration paths are strictly owned by `root:root` with write permissions restricted exclusively to the superuser.

[Audit Target 3: Systemd Timers (`systemctl list-timers`)]
* Purpose: Audits the modern Linux scheduling system to track upcoming background tasks and service triggers.
* Security Risk: Sophisticated attackers use systemd timers instead of cron to hide automatic execution tasks behind legitimate system service names.
* Practical Action: Audited all 12 system timers and confirmed they belong strictly to standard system tasks (log rotation, package backup, temporary file cleanup).

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* System persistence can hide in two different scheduling layers: legacy Cron tables (`/etc/cron*`) and modern Systemd Timers (`systemctl list-timers`).
* Restricting write permissions on `/etc/cron.*` to `root:root` stops standard accounts from escalating privileges via scheduled script injection.
* Periodically auditing scheduled tasks provides continuous visibility into background processes before developing automated response rules.
