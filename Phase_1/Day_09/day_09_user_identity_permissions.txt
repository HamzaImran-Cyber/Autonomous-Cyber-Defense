4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Checking for Hidden Superusers (`root 0`)]
* Purpose: Scans the user database to find any account given complete control over Linux.
* Security Risk: Attackers often create secret accounts with User ID `0` to grant themselves permanent root access without using the name "root".
* Practical Action: Returning only `root 0` confirms no rogue superuser accounts exist on the system.

[Audit Target 2: Identity File Access Controls (`ls -l`)]
* Purpose: Verifies who is allowed to read or change system user and password files.
* Security Risk: If unprivileged users can read `/etc/shadow`, they can copy encrypted password hashes and crack them offline.
* Practical Action: `/etc/shadow` permissions (`-rw-r-----`) restrict access exclusively to root and the shadow group, keeping encrypted hashes secure.

[Audit Target 3: Password Age and Expiration (`chage -l`)]
* Purpose: Checks how often a user must change their password and whether an account expires.
* Security Risk: Passwords that never expire increase long-term compromise risk if stolen or leaked.
* Practical Action: Standard development environments default to `never` (99999 days), but enterprise production servers enforce periodic rotation (e.g., 90 days).

[Audit Target 4: Administrative Rights (`/etc/sudoers`)]
* Purpose: Audits which user groups are allowed to run administrative commands.
* Security Risk: Loose rules can allow standard users to gain root access without entering a password.
* Practical Action: The rules confirm that only the `root` user and members of the `%sudo` group can elevate privileges, requiring standard password authentication.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* User ID `0` is what grants full administrative rights in Linux, not the text name "root".
* `/etc/passwd` is world-readable so applications can map UIDs to usernames, but `/etc/shadow` must remain strictly restricted to protect password hashes.
* Combining `grep -v '^#'` and `grep -v '^$'` strips away background noise to highlight operational security rules instantly.
