4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: DNS Query Tracing (`dig google.com +short` & `dig +trace`)]
* Purpose: Translates human-readable domain names into target IPv4 addresses (`142.250.202.14`) and verifies the delegation chain starting from root nameservers down to authoritative servers.
* Security Risk: Plaintext DNS queries over UDP port 53 can be intercepted, sniffed, or modified via DNS cache poisoning, causing users to be redirected to phishing infrastructure.
* Defensive Action: Security analysts perform manual DNS resolution traces with `dig +trace` to verify that IP responses originate from legitimate authoritative nameservers. Enterprise systems implement DNSSEC validation alongside DoH (DNS over HTTPS) or DoT (DNS over TLS) to encrypt domain lookups.

[Audit Target 2: Routing Path Analysis (`sudo traceroute -I 1.1.1.1`)]
* Purpose: Uses ICMP Echo probes with incrementally increasing Time-To-Live (TTL) values to map each intermediate router hop between the local host and Cloudflare's public DNS (`1.1.1.1`).
* Security Risk: Unmonitored WAN transit routes leave systems vulnerable to BGP hijacking or unauthorized traffic redirection through hostile networks or rogue intermediary nodes.
* Defensive Action: Running regular route tracing baseline audits allows defensive teams to detect abnormal hop deviations, measure hop-by-hop latency spikes, and verify that outbound enterprise traffic stays on expected ISP paths.

[Audit Target 3: Filtering & Timeouts (Hops 3–8 `* * *` in Traceroute)]
* Purpose: Highlights the transition from private virtual/local networks (`172.29.80.1` and `192.168.0.1`) out into public ISP backbones.
* Security Risk: Asterisks (`* * *`) indicate intermediate routers configured to drop diagnostic TTL-expired packets, obscuring exact network topology during active troubleshooting or threat investigations.
* Defensive Action: Switching from default UDP probing to ICMP probing (`-I`) bypasses basic port blocks while maintaining clear visibility of final destination response times (25.7 ms).

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* `dig +trace` bypasses local caches to query root DNS servers (`a.root-servers.net` to `m.root-servers.net`) directly, demonstrating how DNS hierarchy functions under the hood.
* Default UDP traceroute probes are often dropped by middleboxes and ISP firewalls; using `sudo traceroute -I` sends ICMP Echo packets to successfully trace WAN paths.
* Local private hops (`172.29.80.1` and `192.168.0.1`) show sub-10ms latency, while public WAN endpoints (`1.1.1.1`) add realistic physical internet transport latency (~25.7ms).
