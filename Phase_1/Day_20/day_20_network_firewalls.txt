4. PRACTICAL ANALYSIS & OBSERVATIONS
------------------------------------------------------------------------------
* Firewall Stance (UFW): My firewall is active and following a "Default Deny" 
  rule for incoming traffic. This means any unexpected network request from 
  the outside gets blocked automatically. Outgoing traffic is allowed so the 
  system can download updates normally. Port 22 (SSH) is explicitly opened.

* Kernel Packet Filtering (iptables): UFW is actually a simple interface sitting 
  on top of iptables/Netfilter. Looking at raw iptables shows that the default 
  INPUT chain policy is set to DROP. Packets hitting the system pass through 
  UFW's internal chains (`ufw-before-input`, `ufw-track-input`) where connection 
  tracking decides if a packet is safe or rejected.

* Open Ports vs Firewall Protection (ss): 
  - `systemd-resolve` (DNS) is listening on port 53, but it is bound strictly to 
    `127.0.0.53` and `127.0.0.54` (loopback). This means outside devices cannot 
    touch it.
  - `chronyd` (NTP time sync) is listening on port 323, also locked to `127.0.0.1`.
  - SSH (`port 22`) is listening on `0.0.0.0:22` (all network adapters). This 
    directly matches the UFW rule that explicitly allows port 22 incoming.

5. WHAT I LEARNED TODAY
------------------------------------------------------------------------------
* A proper security baseline starts with "Deny All Incoming" and only opens the 
  exact ports needed for work.
* Keeping internal services (like DNS and time sync) bound strictly to localhost 
  (`127.0.0.1`) prevents them from being exposed to the local network in the 
  first place.
* UFW provides a easy way to manage rules, but iptables is the engine doing 
  the real packet filtering inside the Linux kernel.
