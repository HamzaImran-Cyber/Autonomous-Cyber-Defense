4. PRACTICAL ANALYSIS & OBSERVATIONS
------------------------------------------------------------------------------
* Destination IP Frequency Analysis:
  - Running `awk NF | sort | uniq -c | sort -nr` grouped and counted all destination 
    IPs. The count of `5` for `127.0.0.1` confirms that every packet in this capture 
    stayed entirely within the local loopback interface.

* DNS Field Extraction Behavior:
  - The second command gave no output because `capture.pcap` was saved during Day 22 
    using a strict TCP SYN filter. Since these packets are pure Layer 4 SYN handshakes 
    with no Layer 7 DNS payloads, `tshark` found no `dns.qry.name` values, and `awk NF` 
    stripped the empty lines.

* CSV Export Structure:
  - Exporting with `-E header=y -E separator=, -E quote=d` formatted the packet 
    metadata into a clean, double-quoted CSV dataset.
  - Including `_ws.col.Protocol` and `_ws.col.Info` pulled in high-value connection 
    details directly from Wireshark's display engine, capturing source/destination 
    ports, sequence numbers, window sizes, and TCP options (MSS, SACK, TSval, WS).

5. KEY TAKEAWAYS
------------------------------------------------------------------------------
* Combining `tshark -T fields` with standard Linux text tools (`sort`, `uniq -c`) 
  makes it easy to build quick frequency tables for traffic baselines.
* Using double-quoted CSV exports prevents formatting breaks when packet summary 
  strings contain commas or special characters.
* Knowing how packet captures were filtered up front saves time when reviewing empty 
  field extractions during an investigation.
