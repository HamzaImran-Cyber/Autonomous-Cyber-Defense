4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Physical Memory & Swap Allocation (`free -m`)]
* Purpose: Checking active RAM usage (474 MB used out of 3854 MB) and confirming that Swap memory is completely unused (0 MB used out of 1024 MB).
* Security/System Risk: High memory usage or heavy reliance on Swap memory slows system response times and can indicate a memory leak or a denial-of-service condition caused by runaway processes.
* Practical Action: Monitoring RAM and Swap regularly helps defenders identify resource-heavy applications before they crash system services or freeze the host.

[Audit Target 2: CPU Utilization & Process Snapshots (`top` snapshot)]
* Purpose: Capturing real-time CPU idle state (95.6% idle) and identifying top active processes currently drawing system performance.
* Security/System Risk: Unexpected CPU spikes from unknown background tasks can be a sign of unauthorized background scripts, cryptominers, or failing system daemons.
* Practical Action: Using `top` gives quick visibility into system load averages and process states (26 total tasks, 1 running, 25 sleeping) to isolate resource hogs.

[Audit Target 3: Process Ownership & Execution Tree (`ps aux`)]
* Purpose: Mapping running processes to their specific user accounts (such as `root`, `systemd+`, `message+`, `_chrony`) and identifying unique Process IDs (PIDs).
* Security/System Risk: Unrecognized processes running with elevated privileges (`root`) pose a major risk if compromised, as they have full access to system files and settings.
* Practical Action: Auditing the process list with `ps aux` lets defenders verify that only legitimate system services (like `systemd-resolved`, `chronyd`, `cron`) are running with root rights.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* `free -m` breaks down total, used, free, and cached memory, confirming that Linux reserves unused RAM for buffers to speed up system performance.
* The `top` command displays process CPU and memory consumption, showing that the `top` command itself was the highest CPU consumer (9.1%) during the brief snapshot.
* `ps aux` lists process owners, PIDs, and execution paths, making it easy to trace background services back to their configuration binaries (like `/usr/sbin/cron` or `/usr/lib/systemd/systemd-resolved`).
