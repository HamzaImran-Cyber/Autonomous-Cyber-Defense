------------------------------------------------------------------------------
[Audit Target 1: System Attribute Flags (`lsattr`)]
* Purpose: Determine if extended filesystem security attributes are active on core configuration paths.
* Security Risk: Standard Linux permissions (`chmod`) allow root users or processes with root privilege to alter configuration files seamlessly.
* Practical Action: Output shows `--------------e-------` (extents allocation bit set). No immutable (`i`) or append-only (`a`) flags are set by default.

[Audit Target 2: FIM Cryptographic Baselining (`sha256sum`)]
* Purpose: Calculate 256-bit hash signatures for `/etc/passwd`, `/etc/shadow`, `/etc/sudoers`, and `/etc/ssh/sshd_config`.
* Security Risk: Attackers often modify configuration files to add rogue superusers or disable SSH security checks.
* Practical Action: Stored baseline hashes. Any future automated FIM check comparing current hashes against these strings will immediately flag unauthorized file modifications down to a single byte change.

[Audit Target 3: Immutability Tamper Enforcement (`chattr +i`)]
* Purpose: Test the kernel-level write-protection lock.
* Security Risk: Privilege escalation exploits allow attackers to overwrite system binaries or configurations.
* Practical Action: Verified that applying `chattr +i` sets the `i` attribute flag (`----i---------e-------`) and blocks write attempts with `Operation not permitted`.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* Extended attributes (`chattr`) operate below standard permission bits (`chmod`), providing an extra layer of kernel enforcement.
* Setting the `+i` bit on critical files (like `/etc/shadow` or `/etc/sudoers`) stops unauthorized modification attempts, even if an attacker achieves root execution.
* SHA-256 hash baselining forms the core foundation of automated File Integrity Monitoring (FIM) systems.
