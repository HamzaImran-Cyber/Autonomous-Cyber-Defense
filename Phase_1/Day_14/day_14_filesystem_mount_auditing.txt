4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: System Virtual Paths (`/proc`, `/sys`)]
* Purpose: Checks access rules for folders where Linux exposes live kernel and hardware information.
* Security Risk: If users can run scripts inside `/proc` or `/sys`, they can tamper with low-level system settings.
* Practical Action: Confirmed that `/proc` and `/sys` enforce `noexec, nosuid, nodev`, preventing any code execution in kernel memory paths.

[Audit Target 2: Shared Memory Hardening (`/run/shm`)]
* Purpose: Audits temporary RAM storage used by applications to exchange data quickly.
* Security Risk: Shared RAM folders are common targets for attackers trying to hide malicious temporary files.
* Practical Action: Verified that `/run/shm` enforces `nosuid, nodev`, stopping malicious programs from gaining administrative powers via temporary memory.

[Audit Target 3: Disk Error Protection (`errors=remount-ro`)]
* Purpose: Checks how the system disk (`/`) reacts if a hardware or filesystem error occurs.
* Security Risk: Allowing writes on a damaged disk can corrupt security logs and system files.
* Practical Action: Confirmed that `/` includes `errors=remount-ro`, which instantly locks the disk into read-only mode if corruption occurs.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* Applying `noexec`, `nosuid`, and `nodev` to system folders blocks common privilege escalation paths without affecting normal software operations.
* System memory locations (`tmpfs`) run in RAM and clear automatically on reboot, making them prime targets to monitor during security audits.
* Automated fail-safe rules (`errors=remount-ro`) keep filesystem integrity intact during unexpected system crashes.
