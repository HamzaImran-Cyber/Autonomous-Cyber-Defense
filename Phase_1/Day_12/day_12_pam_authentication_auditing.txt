4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: System Security Checklist Directory (`/etc/pam.d/`)]
* Purpose: Stores security rule files for programs like `sudo`, `su`, and `login`.
* Security Risk: If an attacker modifies these files, they could trick tools into letting users log in without a password.
* Practical Action: Verified that all files are locked down so only `root` can modify them (`-rw-r--r--`).

[Audit Target 2: Standard Login Verification (`common-auth`)]
* Purpose: Defines how Linux checks your password when you log in or run administrative commands.
* Security Risk: Weak settings could allow blank passwords or bypass identity checks completely.
* Practical Action: Verified that `pam_unix.so` checks passwords against system files while stopping unauthorized access with `pam_deny.so`.

[Audit Target 3: Password Encryption Strength (`common-password`)]
* Purpose: Controls how new passwords are scrambled before being saved to disk.
* Security Risk: Using old scrambling methods makes it easy for attackers to decode stolen password files.
* Practical Action: Confirmed that Ubuntu uses `yescrypt`, a modern, super-strong scrambling method that protects stored passwords from guessing attacks.

[Audit Target 4: Wrong Password Protection (`faillock.conf`)]
* Purpose: Sets rules for locking out accounts after too many failed password attempts.
* Security Risk: Without lockout limits, automated tools can guess millions of passwords a minute until they get in.
* Practical Action: Audited default settings that lock an account for 10 minutes (`unlock_time = 600`) after 3 bad attempts (`deny = 3`) within 15 minutes.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* Linux uses reusable security checklists (`/etc/pam.d/`) so every tool follows the same login rules.
* `yescrypt` keeps stored passwords safe by making them extremely hard for attackers to crack offline.
* Setting lockout rules stops automated tools from guessing passwords over and over again.
