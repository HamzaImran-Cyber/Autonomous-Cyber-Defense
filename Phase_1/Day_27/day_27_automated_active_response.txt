4. PRACTICAL ANALYSIS & OBSERVATIONS
------------------------------------------------------------------------------
* Script Logic & Token Isolation:
  - The script dynamically checks for `nids_alerts.log` in both the organized directory 
    `Phase_1/Day_26/` and the home folder fallback.
  - Using `awk '/ALERT/ {print $9}'` targets field 9 of the alert string, isolating 
    `127.0.0.1`. Piping into `sort -u` deduplicates IP addresses so `iptables` only 
    processes unique targets.

* Audit Log Trace:
  - Reading `active_response_blocks.log` records both execution attempts: the first 
    failed token attempt (`Probe`), followed by the clean execution that successfully 
    isolated `127.0.0.1`.

* Kernel Netfilter Enforcement:
  - Running `sudo iptables -L INPUT -n -v` confirms the block rule is live.
  - The entry `DROP all -- * * 127.0.0.1 0.0.0.0/0` tells the Linux netfilter framework 
    to discard all inbound IP packets originating from `127.0.0.1` before they reach 
    any user-space application socket.

5. KEY TAKEAWAYS
------------------------------------------------------------------------------
* Combining log parsing with netfilter commands creates a SOAR pipeline that turns 
  passive detection logs into active protection.
* Token column verification in `awk` is essential when parsing custom alert formats 
  to avoid feeding non-IP text strings into firewall utilities.
* `iptables -L -n -v` provides low-level verification of kernel-level traffic drops 
  and packet counters.
