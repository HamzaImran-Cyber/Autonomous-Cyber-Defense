4. ARCHITECTURAL REAL-WORLD APPLICATION & PROBLEM SOLVING
------------------------------------------------------------------------------
[Audit Target 1: Blocking Incoming Traffic (`default deny incoming / allow outgoing`)]
* Purpose: Setting a strict starting rule so no outside computer on the network can connect to my Linux system unless I specifically write a rule to allow it, while still letting my system reach the internet for updates and web browsing.
* Security Risk: If a machine has no active firewall, any service or application running in the background with an open port is exposed to anyone scanning the local network.
* Practical Action: Setting `deny incoming` as the default rule shuts down all unneeded entry points at once, which is the standard safety starting point when setting up any server.

[Audit Target 2: Whitelisting Management Ports (`sudo ufw allow 22/tcp`)]
* Purpose: Adding an explicit rule to allow SSH traffic on TCP port 22 before turning on the firewall engine.
* Security Risk: If you enable a firewall on a remote server (like AWS or DigitalOcean) without allowing port 22 first, the firewall will block your remote connection and permanently lock you out of your own server.
* Practical Action: Getting into the habit of always allowing management ports (like SSH) before running `ufw enable` prevents lockout accidents on remote machines.

[Audit Target 3: Checking Port Sockets with Netcat (`nc -zv 127.0.0.1 80`)]
* Purpose: Testing if port 80 is listening on my local loopback address (`127.0.0.1`) without sending actual web page data or opening a full browser.
* Security Risk: Assuming a port is completely closed just because you didn't configure a web server can lead to missed background services that are secretly listening.
* Practical Action: Using `nc -zv` gives a fast, simple way to check if a port is open and responding locally before deciding whether to block or open it to the network.

5. KEY TECHNICAL LESSONS
------------------------------------------------------------------------------
* UFW provides a simple way to manage the underlying `iptables` packet filtering system built into the Linux kernel.
* `nc -zv` is a lightweight tool for checking if a specific port is listening without sending extra data payloads.
* Local internal traffic (`127.0.0.1`) is allowed by default so programs on the same computer can still talk to each other even when external incoming traffic is blocked.
